### Decisions & Assumptions
- **Next.js 14 instead of 16**: Node v18 is installed on this machine; Next.js 16 requires Node ≥ 20. Tailwind CSS v4's `@tailwindcss/oxide` binary also requires Node 20 and will fail to compile. All Tailwind v4-specific syntax (`@import "tailwindcss"`, `@theme`) was replaced with v3 equivalents.
- **`127.0.0.1` instead of `localhost` in proxy and uvicorn**: Windows resolves `localhost` to `::1` (IPv6) in Node.js but uvicorn binds to `0.0.0.0` / `127.0.0.1` (IPv4) by default, causing `ECONNREFUSED` on the first API call. Hardcoding the IPv4 address in both the Next.js proxy config and the uvicorn startup command eliminates the ambiguity.
- **Agent status moved outside scroll area**: The pipeline tracker was originally inside the scrollable messages div — it appeared at the bottom of the message list and was invisible if the user had scrolled or if the chat was short. Moving it to a fixed slot between the message list and the input bar means it's always on screen while the agent is working.
- **Only `manager` and `summarizer` tokens are rendered**: The Analyst, Reviewer, and Research Team agents produce internal reasoning text (tool call results, JSON dossiers) that isn't meant for the user. Filtering by author name ensures only the final Manager Q&A responses and Summarizer recommendation text appear in the chat.
- **429 error is caught in `session_manager.py`, not `server.py`**: The exception originates inside the `runner.run_async()` async generator. If caught at the FastAPI layer the generator is already broken; catching it at the source lets us yield a proper `error` SSE event and close the stream cleanly before FastAPI sees it.
- **Session history is localStorage-only**: Full message history restoration from the backend would require storing every message — out of scope for this session. The sidebar shows past sessions for reference and allows starting fresh; replaying a past session resets to a new blank conversation.

### Decisions & Assumptions
- **Usage counter increments after a successful HTTP response**, not before. This means a failed or timed-out request doesn't consume a quota slot — only actual successful API calls are counted against the monthly limit.
- **Monthly reset is implicit**: `_load_rentcast_usage()` checks the stored month string against the current month. If they differ (new month), it returns a fresh zero-count object. No cron job or manual reset is needed.
- **Apify `maxItems` is currently 5**, which is already far below the 86-item guardrail ceiling. The guardrail is latent protection — it activates only if the requested count is ever raised.
- **Per-run RentCast counter (`_rentcast_run_count`) lives in module memory** and resets when the process restarts. This maps naturally to "one agent session = one run" since `main.py` starts a fresh process each time.
